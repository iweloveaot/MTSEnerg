# МТС EnergyTool · участник Б · день 4

Для сборки выбран текстовый поиск с обратным индексом. Контекст содержит до пяти целых разделов Markdown с заголовками, списками и таблицами. На 18 рабочих примерах сокращение контекста до четырёх разделов убирало часть отмеченных источников в двух случаях.

## Сравнение поиска

На каждом рабочем примере использовались идентификаторы разделов, которые подтверждали ответ в локальной проверке дня 2. Метрика учитывает наличие хотя бы одного или всех отмеченных источников в первой пятёрке. Другие подходящие разделы тоже могут содержать ответ. Шесть отдельных формулировок из дня 2 использованы для контрольной проверки после выбора метода и размера контекста.

| Метод | Рабочие · хотя бы один | Рабочие · все | Контрольные · все | Медиана по рабочему набору |
| --- | ---: | ---: | ---: | ---: |
| Текстовый, обратный индекс | 18/18 | 18/18 | 6/6 | 0,117 мс |
| Векторный, TF‑IDF по тройкам символов и косинусная близость | 15/18 | 8/18 | 4/6 | 1,260 мс |
| Гибрид, объединение первых 15 результатов каждого метода по RRF | 17/18 | 15/18 | 5/6 | 1,384 мс |

Замеры локальные, на 233 разделах, без генерации и сетевых вызовов. В отдельном сравнении одинаковых запросов медиана текстового поиска снизилась с 0,445 до 0,114 мс. Порядок найденных разделов совпал с предыдущей версией во всех 38 сценариях из дней 2 и 3.

Для векторного прогона использован локальный TF‑IDF. Загрузка модели E5 не получила разрешения на выполнение команды. BGE‑M3 и модельный реранкер отдельно не измерялись. Для рабочего набора отмеченных источников выбранный метод уже даёт 18/18, поэтому дополнительное ранжирование в этот кандидат не включено.

## Консультация и проверка

Промпт требует проверять, отвечает ли найденный фрагмент на конкретный вопрос. Когда подтверждена только часть ответа, консультант сообщает её и обозначает, чего не хватает. При нехватке сведений об объекте он задаёт один вопрос. При отсутствии нужного факта по теме EnergyTool он может предложить специалиста. Для вопроса вне темы он обозначает область консультации. Это правило применяется в промпте. Код проверяет формат, идентификаторы источников и числовые суммы в рублях по указанным разделам.

На архиве организаторов прошли 56 автоматических тестов. Повторно прогнаны 38 сценариев дней 2 и 3 и ещё три сценария о недостаточности сведений. Для генерации использованы подготовленные ответы, включая ошибочный JSON и неподтверждённую цену для проверки обработки ошибок. Этот прогон показывает доступность источников и обработку результата приложением. Качество ответов реальной Qwen и задержку чата нужно измерить в общей сборке.

## Параметры для А и контрольные вопросы для В

А может взять `lexical-focus-v4` и `consult-v4`. Индекс строится один раз из архива. Параметр `top_k=5`, порядок и формат источников остались совместимыми с текущим вызовом. Корневой модуль для сборщика уже обновлён. Задержку полного ответа стоит снять на подключённом API модели.

Контрольные случаи для В — `H01` ручной сбор и фото, `H02` четвёртая категория в короткой реплике, `H03` вводные для сметы по складу, `H04` смена темы на солнечную станцию, `H05` архив потерь за полгода и `H06` фото показаний счётчиков воды. Формулировки и ответы лежат в локальном журнале `qa-local/day2_consultation.jsonl`. Ранги по этим случаям есть в `qa-local/day4_retrieval_optimized.json`. Для оценки работы модели полезно отдельно сверить, сохранила ли она условия из найденных разделов.
