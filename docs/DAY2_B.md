# МТС EnergyTool · участник Б · день 2

Первая версия консультации готова для подключения к обработчику участника А. Поиск `lexical-focus-v2`, промпт `consult-v2`. В отчёте по-прежнему используется ручная имитация генерации по фрагментам, которые реально вернул поиск.

## Что изменилось

При неоднозначной короткой реплике поиск уточняет запрос по контексту разговора. Он учитывает связку между фото и учётом, отсылку к ценовой категории и запрос исходных данных для оценки платформы. Явная смена темы начинает новый поиск, а модель по-прежнему видит весь диалог. Лимит в проверке — пять фрагментов.

Промпт предлагает отвечать прямо, задавать один конкретный вопрос при нехватке вводных или предлагать специалиста. Цена, сроки и эффект для конкретного объекта требуют расчёта. При указании ценового ориентира нужны единица, период и оговорки из источника. Для ответа с числовой суммой в рублях код проверяет, что эта сумма встречается в процитированном фрагменте. Смысл обещаний, применимость суммы и остальные факты проверяются по источнику.

| Пример | Результат |
| --- | --- |
| № 10 · вырос счёт | Раздел о причинах роста счёта поднялся со второго на первое место. В первой пятёрке остались фрагменты про солнечную генерацию |
| № 15 · счётчики в бизнес-центре | Поиск нашёл учёт по арендаторам и распознавание показаний по фото для неподключённых приборов |
| № 17 · четвёртая категория | Поиск нашёл условия категории и общую диагностику счёта. Ответ учитывает, что клиент назвал категорию предположительно |
| № 18 · предварительная оценка | Поиск нашёл вводные по платформе. Ответ перечисляет параметры трёх складов для оценки и продолжает разговор без запроса телефона |

## Локальная проверка

В локальном журнале `qa-local` записаны вопрос, последняя реплика, найденные и использованные источники, ответ и результат проверки формата для каждого случая. Каталог указан в `.gitignore`. В журнале 18 рабочих примеров организаторов, 6 отдельно проверенных формулировок, 3 сценария поведения и 2 проверки некорректного ответа. Дополнительные формулировки проверяют перенос на похожие вопросы и смену темы. Это локальный набор для проверки, без оценки на скрытой выборке платформы.

Все 29 сценариев вернули ожидаемое действие. В контрольных случаях неверный JSON и неподтверждённая числовая цена дали отдельные коды ошибки генерации. Пробел поиска виден по списку найденных разделов и проверяется отдельно. Медиана поиска — около 0,46 мс на этой машине. Семь автоматических проверок прошли.

```powershell
$env:ENERGYTOOL_QA_DATA = "$env:USERPROFILE/Downloads"
python -B -X utf8 -m unittest discover -s tests -p test_energytool_rag.py -v
```

Без `ENERGYTOOL_QA_DATA` две проверки по архиву организаторов пропускаются. Остальные используют тестовые данные в памяти.

## Передача участнику А

`SearchIndex.from_zip(path)` строит индекс один раз. Для каждой независимой строки CSV обработчик вызывает `consult(index, parse_question(question), generate)`. В `generate` приходит список сообщений для модели, обратно ожидается строка с JSON. В `submission.csv` достаточно взять `result.answer`. Для отладки доступны `result.action`, `result.sources` и `result.generation_issue`. Последнее поле отличает корректную рекомендацию специалиста от запасного ответа при ошибке генерации.

По локальной проверке модуль можно подключать к первому сабмиту. Для заключения о готовности всей сборки нужен прогон обработчика А на целевой модели с проверкой выходного CSV. Сборки А и оценки платформы в рабочей папке пока нет.
