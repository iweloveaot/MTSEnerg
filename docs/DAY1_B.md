# МТС EnergyTool · участник Б · день 1

Поиск запускается локально по архиву организаторов. Код читает Markdown напрямую из ZIP и строит индекс в памяти. Каждый фрагмент содержит цельный раздел, включая его список или таблицу. Идентификаторы стабильны для одной версии архива. Номер строки указывает на заголовок раздела.

## Проверка

Из каталога проекта в PowerShell с Python 3.11 или новее.

```powershell
python -B -m unittest discover -s tests -p test_energytool_rag.py -v
python -B -X utf8 energytool_rag.py "$env:USERPROFILE/Downloads/knowledge-base.zip" --question "Можно установить солнечные панели на двух скатах?"
python -B -X utf8 energytool_rag.py "$env:USERPROFILE/Downloads/knowledge-base.zip" --questions "$env:USERPROFILE/Downloads/demo_questions.csv" --top-k 5
```

В последней команде на каждый ID выводится одна строка JSON с результатами поиска. Она содержит фрагменты базы, поэтому хранить такой вывод следует локально. Для автоматического сабмита А формирует отдельный `submission.csv` с колонками `id,answer`. Платформа передаёт архив базы и вопросы. Регламент разрешает добавлять в ZIP корневые Python-модули и исключает готовый индекс и файлы данных. Публичный сайт охватывает больше направлений, чем предоставленная база. Для ответов о продуктах используется архив кейса. [Сайт EnergyTool](https://energytool.mts.ru/)

## Передача участнику А

- `SearchIndex.from_zip(path)` строит индекс один раз. `index.search(messages, top_k=5)` возвращает ранжированные пары `source` и `score`. Балл предназначен для ранжирования и не является вероятностью правильного ответа.
- `parse_question(question)` принимает поле `question` из CSV. Для чата можно передать список сообщений `{"role": "user" | "assistant", "content": "..."}`. Каждый вызов получает историю только текущего диалога.
- `consult(index, messages, generate, top_k=5)` вызывает адаптер `generate(prompt_messages) -> str` и возвращает `action`, `answer` и использованные `sources`. Действия — `answer`, `clarify`, `specialist`. В отладке показывать `document_id`, `section_id`, `path`, `headings`, `line`. Ошибки самого адаптера обрабатывает вызывающий код.
- Формат предварительный. Нужны структура общего репозитория и сигнатура адаптера А. Промпт просит структурированный JSON и проверяет идентификаторы источников. Проверка идентификаторов сама по себе не подтверждает все факты в ответе.

## Передача участнику В

В резюме для менеджера отделять слова клиента от предложений консультанта. Фиксировать тип компании и объекта, задачу, обсуждённое решение, известные параметры с единицами, нерешённые вопросы и следующий шаг. Включать источники, когда консультант сообщил конкретное условие по продукту. Если клиент передумал или поправил параметр, использовать последнюю версию. Не заполнять пробелы догадками и не требовать телефон для продолжения консультации. ФИО, телефон и компанию собирать для заявки в соответствующем сценарии.

## Прогон с имитацией модели

Через `consult()` прогнали 18 примеров организаторов и три дополнительных сценария. Ответы составлены вручную по истории диалога и пяти фрагментам, которые поиск действительно передал адаптеру. Все 21 ответ прошли проверку формата и идентификаторов источников. На общий запрос консультант задал уточняющий вопрос, а по монтажным параметрам счётчика и отключению за долги предложил специалиста.

Сверка с примерами ответов подтвердила три пробела в подборе источников. В № 15 можно посоветовать начать со списка приборов по арендаторам, но для полноценного ответа нужен фрагмент про распознавание показаний с неподключённых приборов. В № 17 можно объяснить, какие строки счёта сравнить, но не хватает условий четвёртой ценовой категории. В № 18 консультант продолжил разговор без телефона и предложил собрать данные по складам. Профильный раздел помог бы явно указать модели и количество приборов по каждому объекту.

Этот прогон проверяет путь от поиска до принятого модулем ответа. Результат относится к ручной имитации. Качество генерации, задержку и стабильность формата Qwen можно измерить после подключения модели.
