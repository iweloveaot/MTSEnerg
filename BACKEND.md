# Backend участника А

## Запуск (Python 3.9)

Из корня проекта в PowerShell:

```powershell
py -3.9 -m venv .venv
.venv/Scripts/python.exe -m pip install --upgrade --force-reinstall -r requirements.txt
# Если .env ещё нет: скопировать .env.example в .env и заполнить настройки.
.venv/Scripts/python.exe -m uvicorn backend.app:create_app --factory --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000/. Frontend и API доступны с одного адреса.
Зависимости, включая косвенные (`click`, `anyio`, `jiter` и другие), закреплены
для Python 3.9. Если окружение раньше заполнялось через другой Python,
переустановите зависимости приведённой командой: изменение `requirements.txt`
само по себе не заменяет уже установленные пакеты и бинарные расширения.
Не устанавливайте `uvicorn`, `fastapi` или `openai` без указания файла зависимостей.
Запускать одним процессом (без `--workers`): блокировки диалогов находятся в памяти.
Файлы участника В не изменены. База по умолчанию — `backend/data/sessions.sqlite3`;
все успешно обработанные диалоги сохраняются, включая диалоги без заявки.
Новый UUID из кнопки «Новый диалог» начинает пустой контекст; прежний остаётся в базе.

## Общая обработка

`backend.service.process_message(message, model=..., session_id=None, history=None,
application_requested=False)` принимает историю до текущего сообщения и возвращает:

```json
{
  "answer": "Ответ",
  "session_id": "uuid",
  "processing_time_ms": 123.45,
  "sources": [],
  "application": {}
}
```

`application` — результат существующего сериализатора участника В.
`ChatService` добавляет сохранение истории и последовательную обработку одной сессии.
В модель передаются последние 40 сообщений; полная успешная история остаётся в SQLite.
При ошибке модели текущий ход не сохраняется и может быть повторён.
`processing_time_ms` измеряет общую обработку сообщения до записи в SQLite, без сети браузера.
Неизменённый frontend продолжает показывать время запроса, измеренное в браузере.

`solution.solve(message, history=None)` вызывает тот же обработчик без сохранённых
веб-сессий. Импорт `solution` не обращается к сети. Локальная проверка:

```powershell
.venv/Scripts/python.exe solution.py "Здравствуйте"
```

Это пока локальный адаптер, а не готовый сабмит платформы.
После изучения официального `sample_submission.zip` и технического регламента
подтверждены требования: запуск `python solution.py` без текстового аргумента,
чтение `DATA_DIR/questions.csv` (по умолчанию `data`), создание `submission.csv`
в рабочем каталоге с колонками `id,answer`, по одному непустому ответу на каждый ID.
Каждый тест-кейс независим; история, если есть, передаётся внутри `question`.
Максимальная длина ответа — 10000 символов.

В окружение платформы переносятся только корневые `.py` и `requirements.txt`:
текущие пакетные импорты из `backend/` и `application_agent/` для такого ZIP
не подходят. Нельзя просто заархивировать репозиторий. Также для сабмита нужно
использовать разрешённые зависимости из материалов организаторов;
в минимальном примере указана `httpx==0.28.1`. Полный `requirements.txt`
в этом репозитории предназначен для веб-прототипа.
Вопросы, базу знаний, `.env`, данные и индексы включать в ZIP запрещено.

Источник: https://docs.google.com/document/d/1wZsqH4xXZXwjiAJCtFQGjTaLxEU3D_tMCSw0yXcbQ0U/edit

Версии веб-зависимостей подобраны с поддержкой Python 3.9. Аннотации моделей
HTTP используют `Optional[str]`, чтобы Pydantic мог вычислять их на Python 3.9.
Одного `from __future__ import annotations` для поля `str | None` недостаточно:
фреймворк читает типы во время выполнения.
Если `.venv` сообщает `Unable to create process`, проверьте путь `home` в
`.venv/pyvenv.cfg`: он должен указывать на существующую установку Python 3.9.

## HTTP

- `POST /api/chat`: `{"session_id":"uuid-из-frontend","message":"Текст"}`.
  Если идентификатор отсутствует, сервер создаёт его. Существующий frontend создаёт UUID сам.
- `GET /api/health`: жив ли backend; не вызывает модель.
- `GET /api/ready`: реальный короткий запрос к настроенной модели; расходует запрос API.
- Ошибки модели: `{"error":{"code":"model_timeout","message":"..."}}`.
  Таймаут — 504, неверный ответ — 502, недоступность/авторизация/настройки — 503.
  Ошибка валидации запроса — 422. Ключи и тела ошибок провайдера наружу не передаются.
  Существующий frontend показывает общее сообщение ошибки и разблокирует ввод.

## Заявка и границы текущей версии

Для явного согласия отправить отдельным сообщением «Хочу оформить заявку»
(также «Оформите заявку», «Оформить заявку», «Оставить заявку», «Хочу оставить заявку»).
Далее существующий агент задаёт вопросы и готовит карточку. Неоднозначные фразы
не включают сбор контактов. Отказ обрабатывает агент В; консультация продолжается.
Заявка сохраняется как часть истории и восстанавливается агентом; отправки в CRM нет.

Поиск участника Б ещё не подключён: `sources` пуст, системная инструкция запрещает
модели придумывать продуктовые сведения. Точка подключения — адаптер генерации в
общем обработчике; после интеграции поиска нужно возвращать реальные источники.
Настройки модели берутся из `.env`: `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`,
необязательный `LLM_TIMEOUT_SECONDS` (по умолчанию 30, без автоматических повторов).
SQLite предназначена для локального прототипа; доступ по UUID не заменяет авторизацию.

## Проверки

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe -m unittest discover -s backend_tests -v
```

Новые тесты используют подставную модель без сетевых запросов: проверяют HTTP,
статику, историю и перезапуск, изоляцию сессий, согласие/отказ, обработку ошибок
и общий обработчик `solution.py`.
