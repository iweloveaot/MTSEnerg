# Запуск решения участника А

Точка входа — `solution.py`. Текущая версия проверена на Python 3.9; устанавливать новую версию Python не требуется.

## Пакетная обработка для платформы

```powershell
python solution.py
# Локальные вопросы и база из корня проекта:
python solution.py --data-dir .
```

Без аргументов читается `$env:DATA_DIR/questions.csv`; Если DATA_DIR отсутствует или пуст, сначала проверяется папка `data` в рабочем каталоге, затем корень проекта. Явно заданный путь имеет приоритет. Если questions.csv отсутствует, выводится его ожидаемый полный путь и инструкция по запуску. Там же ожидается `knowledge-base.zip`. Для локального запуска допускается архив из корня проекта; `KNOWLEDGE_BASE_PATH` задаёт явный путь. Результат — `submission.csv` в рабочем каталоге, колонки `id,answer`. ID и порядок сохраняются, каждый вопрос получает независимую историю. История внутри поля question разбирается модулем Б. Индекс и HTTP-клиент создаются один раз на пакет.

Настройки модели: `LLM_API_KEY`, `LLM_BASE_URL` (включая `/v1`), `LLM_MODEL`, необязательный `LLM_TIMEOUT_SECONDS`. Также поддерживаются `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`. При установленном python-dotenv локальные настройки читаются из `.env`; файл не включается в сабмит. На платформе настройки задаются окружением. Значения по умолчанию модели и адреса не угадываются: сверить их с актуальным окружением организаторов.

`python solution.py "Вопрос"` печатает JSON одного ответа с источниками и состоянием заявки. При HTTP 429/502/503/504 выполняются до трёх повторов с ограниченной паузой (учитывается числовой Retry-After). При сохраняющемся сбое API пакет завершается с ошибкой, частичный CSV не публикуется; предыдущий готовый CSV сохраняется. Ошибки формата генерации, обработанные модулем Б, возвращают его запасной ответ специалиста.

## Архив сабмита

```powershell
python build_submission.py
```

Создаёт `submission.zip` только с корневыми Python-модулями и `requirements.txt` (`httpx==0.28.1`). В нём нет backend, frontend, базы знаний, вопросов, индексов, `.env` или ключей. Копия `energytool_rag.py` сохраняется без изменений; копии application_agent получают корневые имена и адаптированные импорты только внутри архива. Исходные файлы Б и В не редактируются. Установка веб-зависимостей для сабмита не требуется. Загрузка на платформу выполняется отдельно.

## Веб-чат

```powershell
python -m pip install -r requirements.txt
python solution.py --serve
```

Открыть http://127.0.0.1:8000/. Можно задать `--host` и `--port`. Использовать один процесс: блокировки сессий локальные. Backend вызывает тот же обработчик RAG и заявки, отдаёт реальные пути источников строками для существующего интерфейса В. Индекс кешируется при первом запросе; после замены базы перезапустить сервер.

`POST /api/chat`: `{"session_id":"uuid","message":"Текст"}`. `GET /api/health` проверяет сервер; `GET /api/ready` делает запрос к модели. Ошибки модели возвращаются в поле error: таймаут 504, некорректный ответ 502, доступ/настройки 503. История всех успешных диалогов хранится в SQLite (`SESSION_DB_PATH`, по умолчанию backend/data/sessions.sqlite3); неуспешный ход не сохраняется. Новый UUID начинает чистый контекст.

Явное сообщение «Хочу оформить заявку» включает агента В. Он собирает контакты, учитывает отказ и формирует резюме. Заявка доступна в карточке, отправка в CRM не реализована. Консультации, уточнения и предложение специалиста формирует модуль Б на основании базы знаний. Общая обработка находится в orchestration.py; HTTP-адаптер и хранение — в backend/.

## Проверки

```powershell
python -m pip install -r requirements-dev.txt
python -B -m unittest discover -s backend_tests -v
python -B -m unittest discover -s tests -v
python -B -m unittest -v test_energytool_rag
```

Новые проверки включают независимость историй, сохранение ID, непубликацию частичного CSV, передачу промпта, импорт плоского архива и настоящий запуск `python solution.py` из распакованного архива с тестовым HTTP-сервером. Качество целевой модели и балл платформы проверяются отдельно.

## Пустой ответ модели

Для пустого content выполняются до трёх попыток. Если finish_reason=length, лимит вывода растёт от LLM_MAX_TOKENS (по умолчанию 1500) до LLM_MAX_TOKENS_LIMIT (по умолчанию 6000). Рассуждения модели не используются вместо ответа. После повторного сбоя выводятся ID вопроса, finish_reason, расход токенов и текущий лимит. Пакет показывает прогресс в stderr; итоговый CSV по-прежнему создаётся только после успешной обработки всех вопросов.
